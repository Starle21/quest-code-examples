environment [browser runtime]
- soft real time - respond in timely manner
    - [browser needs to repaint every 16ms to keep animations smooth]
    - [browser has one main thread that it shares with JS, where it does repaints]
- interactive program - user can make changes to content/state/data, user is in control,
    - x batch mode programs - developer is in control
      - waiting for user input, blocking the thread
- distributed - client/server communication
- concurrent browser
    - async 
    - multiple execution flows are in progress
      - threads(web workers), scheduler - event loop with queues
  - nondeterminism creeps in 
    - not having control of ordering of callback functions
    - various order or user events
    - various order of network communication
- event loop (with task queue) that is on the main thread - owned by the browser, 
    - main top level process of a browser - core browser loop

=> control with declarative functional core that performs calculations
    (?? different ordering (reduction steps) of functions produces the same result)
    - have only controlled places where nondeterminism can be
    (track what changed, perform calculations and actions only when sth needs to change)
    (when I need to have control over the order)
    (and control how many times some effect gets performed)
    (otherwise keep immutable data structures)

reactivity
- having an "auto sync system", "built in mechanism" between JS --> DOM
  and between other derived data from primary data in JS
- all the time adhering to function relation, unlike in most programming languages, 
  where equals sign is just one time assignment of a value,
  gets evaluated at the place there
  (like a spreadsheet)
- it is a term with other and broader meaning though, related to real time systems,
  robustness, concurrency, distributed systems
- code has to always be somehow "automatically" connected, or it wouldn't work in runtime
  - someone had to write underlying system, or application developers have to write it manually
  - observers and events
  - functional pipeline of data transformations
  - dataflow paradigm (nodes wait until all inputs are bound)
  - FRP, behavior, events, explicit time, streams, RxJS
